# ADR-0054 — The traffic list's filter is a matcher, and the box and the pills are two front-ends over one evaluator

- Status: Accepted; implemented in `shared`. `cd studio && ./gradlew :shared:jvmTest` is green (`TrafficFilterTest` 24, `TrafficQueryTest` 35). First ADR for the traffic-list view filter, which shipped undocumented — the device-side Capture Filter it is often confused with is ADR-0029.
- Context: The view filter had one comparison: case-insensitive `contains`. Every structured pill was "field contains value", and the box was a plain keyword search over URL/method/code with a placeholder that said so ("Keyword…", plus a code comment reading "No query language yet"). That is enough to find a request and nothing more. The questions an inspector is actually opened for — *show me the failures*, *hide the analytics chatter*, *just these two endpoints* — are all things `contains` cannot express: there is no way to say "not", no way to say "400 or above" (`status:5` as a stand-in for 5xx is a substring accident, not a comparison), and no way to say "either of these". The ask was to enrich it toward a Kibana-style language, filterable from the UI *and* from the box, with matchers beyond `contains`.
- Decision:
  - **Two independent surfaces, AND-ed, that never render into each other.** The box is typed query text; the pills are structured clauses built through `+ Add filter`. This is Kibana's own split, and the reason to keep it is what the alternative costs: a single source of truth needs a *printer* as well as a parser, and every pill would have to round-trip through text losslessly — so adding a pill would rewrite what the user typed, and a query the printer cannot express would be a pill that cannot exist. Keeping them separate means neither surface constrains the other's design.
  - **What they do share is the evaluator.** Both compile to the same `FilterClause` and the same matcher semantics, so `url:orders` typed in the box and a URL-contains-orders pill are the same predicate by construction rather than by two implementations agreeing. This is the whole reason the split is safe.
  - **Matchers: contains, is, wildcard, regex, and the four numeric comparisons — each negatable.** Negation is a flag on the clause rather than a doubled enum, so it reads as "does not contain" in the UI and De Morgan falls out for free on a multi-value clause.
  - **Disjunction lives inside a value, not between terms.** A clause holds a *list* of values and matches if any of them does, which covers "is one of" — the one place `or` is actually wanted — without making the box an expression language with precedence and parentheses to scan. The query grammar stays a flat AND of terms, which is the property that lets you read a query left to right.
  - **The numeric matchers' negations are not their mirrors, and the labels say so.** `not (status > 400)` and `status <= 400` differ on a row with no response code yet: the first keeps it, the second does not. So the UI offers the four comparisons affirmatively and renders a parsed negation as "not >", rather than as a `<=` that would make two different filters look identical.
  - **The value's shape can promote the operator's matcher.** `:` means contains and `=` means exact, but a value containing `*` is a wildcard and a value fenced in `/…/` is a regex, under either. Someone who types a star means a star; reading it literally would be a silent surprise. Quoting opts out of both.
  - **A regex needs slashes at *both* ends.** URLs are made of slashes, so `url:/api/v1` has to stay a literal path fragment — only the closing delimiter distinguishes the two, and getting this wrong would misread the single most common thing anyone types.
  - **One operator per term, and a value runs to the next space.** `https://`, `?a=b` and `:` are exactly the characters that are operators elsewhere, so a value scanned like a field would chop every URL at its scheme.
  - **Malformed input degrades; it never errors and never blanks the list.** An unrecognised field falls back to the plain-keyword reading of the text as typed (`foo:bar` searches for "foo:bar", and a bare `https://host/path` stays one term). A *known* field whose value isn't usable yet — mid-typing, or nonsense for that comparison — is dropped instead, constraining nothing. Which means every prefix of a query someone is halfway through typing still leaves a useful list on screen, and the box needs no error state at all.
  - **Wildcards reuse the device rules' glob**, the same split-on-`*`, escape-the-rest scheme as Map Local and breakpoints (`WailoMatching.kt`, `seedUrlMatches`), so a pattern copied from a rule selects the traffic that rule acts on. Case-insensitive here, unlike those: this is a lens typed by hand, not a wire contract.
  - **The box completes as you type, out of the traffic actually captured.** Field names after the first character, then that field's own values once an operator lands — inside a half-typed `(a or b` group too, and through the `-` and spaced-out forms of a term. This is the other half of discoverability: the `?` card teaches the *shape* of the language, completion teaches the *contents of this capture*, which no reference card can. Values get no minimum-prefix gate (unlike the modal's three characters) because naming a field has already narrowed the pool to one column, so the whole of it is worth seeing the moment the operator is typed. Nothing is offered for a value being *authored* rather than picked — a quoted string, a wildcard, a regex — nor for a term already finished with a space, which would spring a menu open after every word.
  - **The predicate is compiled once per filter change, not once per row.** `TrafficFilter.compile()` parses the query and builds every pattern up front and hands back a `(FlowEntry) -> Boolean`; a `Regex` built inside the row loop would be recompiled once per captured exchange — up to the retention cap — for every keystroke's worth of typing.
  - **Fields stay the five the list already shows** (method, URL, status code, client, edited), so a value that reads on a row is a value the filter can match.
- Alternatives considered:
  - **One query string as the single source of truth, pills rendered from its AST:** rejected — see above; it buys bidirectional editing at the cost of a printer, lossless round-tripping, and pills that can only express what the printer can write.
  - **Full boolean algebra in the box (`and`/`or`/`not`, parentheses):** rejected — the cost is a real expression grammar and a query nobody can scan at a glance, and the only disjunction anyone actually asked for is "is one of", which the value list already covers.
  - **An inline syntax error in the box, Kibana-style, holding the last valid query:** rejected — a list that freezes mid-word while a red underline explains why is worse than one that keeps narrowing as far as it can. Degrading needs no error surface and no explanation.
  - **A distinct "matches wildcard" operator in the text grammar:** rejected — it would mean two spellings for one idea, since a star in a value can only mean one thing anyway.
  - **Expanding to headers, bodies, host/path, duration, sizes, device/platform:** deferred, not rejected. Bodies in particular would decode bytes for every row on every keystroke, and the five-field scope is what keeps the filter agreeing with the columns. The matcher model is field-indexed, so adding one later is a new `FilterKey` and a row accessor.
- Consequences:
  - `FilterClause` went from `(key, value)` to `(key, matcher, values, negated)`, so the pill now reads as a sentence — "URL does not contain analytics", "Method is one of GET, POST" — built by `FilterClause.label()` rather than string-concatenated at the call site.
  - The add-filter modal grew a matcher dropdown between the field and the value, populated per field: only Status Code offers the comparisons, and Edited offers only "is", so an impossible pairing can't be built. `canAdd` validates against the chosen matcher (a comparison needs a number, a regex needs to compile), which is what stops a committed pill from looking fine and silently matching nothing.
  - Several values are entered with a **comma**, which banks what precedes it as a chip. Enter stays "commit the clause" and a suggestion click stays "fill the field only" — both behaviours the modal already had, and a token field that stole Enter would have broken them.
  - The URL autocomplete pool is now matcher-aware. It offered *hosts* while the clause matched the *whole* URL, which was harmless under contains and would have matched nothing under the new exact and wildcard matchers; those two get whole URLs instead. The URL pool is built lazily, since it costs a pass over every captured row and most sessions never open it.
  - `CompactOutlinedTextField` gained a `trailingIcon` passthrough (the decoration already had one) for the box's `?`, which opens the syntax reference — one worked example per thing the grammar can do, because a language this small is taught faster by examples than by prose, and none of it is guessable from an empty box. New icon: `ic_help` (Material Symbols Rounded, weight 400, fill 0).
  - `TrafficFilter.matches(entry)` survives as the one-row form used by tests; it compiles per call, so the viewer holds a `compile()`d predicate across the list instead.
  - Completion reads the *live* text, not the debounced copy the filter runs on. It hands back a span (`QueryCompletion.start`) that an accepted suggestion is spliced at, so a lagging copy would splice into a string that had already moved on. `completionAt` guarantees `prefix == query.substring(start)`; the tests assert that invariant on every case, including the half-typed garbage ones, because breaking it corrupts the query rather than merely offering the wrong list. Escape dismisses the list before it closes the bar, so escaping a menu can't also throw away the query behind it.
  - The bar's arrival broke the detail panel's ceiling, which had reserved a constant 160dp above the traffic list. That chrome is now **measured** (`onSizeChanged`) and the ceiling is `height − chrome − 120dp`, so dragging the panel up can no longer eat the list or run under the header. The constant was already wrong for the bookmark bar and for large text scales; measuring fixes all three at once rather than growing the reserve to cover the worst case and wasting it the rest of the time.
  - **The modal reveals itself one answer at a time.** The value field (and its chips and hint) doesn't exist until both dropdowns are answered, so the card opens as a single question — which field? — rather than a form with a box you can't usefully fill. That moved two things: Escape is now owned by the card (a preview handler above every child) instead of by the value field, which isn't there at open; and the card itself takes focus on open, because otherwise focus would sit in the query box behind the scrim, where Escape would close the whole filter bar out from under the modal and keystrokes would land in the query being dimmed. Focus is pulled into the value field from an effect rather than from the picker's `onSelect`, since at `onSelect` time the field it wants to focus has not been composed yet.
  - **The modal's autocomplete waits for a real stem — with no exceptions.** It is debounced (`AutocompleteDebounceMillis`) and withheld below `MinSuggestionChars`, both of which it already did, except for Edited: its two-value space was offered unprompted, so picking that one field popped a list open the instant it was chosen. Removing the exemption costs nothing (the placeholder already reads "true or false") and buys a rule with no "except".
  - The modal's field and matcher dropdowns wrap their own current label instead of sharing the row's width. Stretched to fill it, they read as two unrelated controls at opposite ends of a gap, when what they are is one phrase — field, then comparison, then value. Wrapping means the matcher shifts when a longer field is picked; that is the accepted cost, and a fixed width sized for the longest label ("does not match regex") only trades the jump for a permanent gap. It works at all because these route through `OutlinedTextFieldDefaults.DecorationBox` directly — Material's 280dp minimum lives on the `OutlinedTextField` *composable*, not on the decoration.
  - Manual smoke (two-tier verification): with traffic captured, Cmd/Ctrl+F → the box now reads "Search or query…". Type a bare word → it filters over URL, method and code exactly as before. Type `status >= 400` → only failures; `-url:analytics` → that host's chatter disappears; `method:(GET or POST)` → both verbs; `url = https://api.example.com/*` → only that host, and the same pattern without the star matches nothing (it is anchored); `url:/orders\d+/` → the numbered paths. Type `url:/api/v1` → treated as a path fragment, not a regex. Type `url:https://api.example.com/v1?a=b` → the whole URL is one value, not split at the scheme. Half-type `status >=` and pause → the list stays as it was rather than emptying, and finishes filtering once the number lands. Completion: type `me` → the field list narrows to `method:`, Enter takes it; keep typing → the verbs seen in this capture, ↑/↓ walk them and the list scrolls to follow, Enter fills one; type `status:` → every code captured, with no prefix needed; `method:(GET or ` → the verbs again, and picking one lands *inside* the group; `url:` → hosts, `url=` → whole URLs. Esc once → the list goes; Esc again → the bar closes and clears. Open `+ Add filter` → only the two dropdowns are there, sitting side by side as one phrase, and Escape closes the card without touching the bar behind it. Pick Status Code → the value appears already focused, and the matcher list offers the comparisons; pick Edited and confirm it offers only "is" and that no suggestion list opens until three characters are typed. Type `GET, POST` into a Method value → two chips, Backspace on the empty field takes one back, Add → a pill reading "Method is one of GET, POST". Pick URL + is → the suggestions are whole URLs; switch to contains → they are hosts again. Remove a pill → its constraint lifts and the box's query stays untouched. Select a row and drag the detail panel's handle to the top → it stops with the traffic list still visible, never under the header; open and close the filter bar while it is at its ceiling → the panel gives back the space the bar needs. Check the pills, the chips, the matcher dropdown, the completion list and the syntax card in both light and dark (ADR-0016).
