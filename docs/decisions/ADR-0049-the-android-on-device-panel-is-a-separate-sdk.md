# ADR-0049 — The Android on-device panel is a separate `sdk-android-panel` artifact with a launcher icon of its own

- Status: Accepted; implemented in `sdk-android-panel`. Mirrors ADR-0038/0047 for Android.
- Context: The panel from ADR-0035 has to exist on Android too, and it needs Compose, a camera permission and a QR decoder — none of which belong in an artifact that ships inside third-party release builds (invariant #3). iOS solved this with a separate `WailoSDKDebug` product; Android has a better version of the same idea available, because Gradle variants can enforce it.
- Decision:
  - **A separate module wired as `debugImplementation`.** Compose, ZXing and the `CAMERA` permission merge into the debug manifest and are absent from release — verified on the sample's merged manifests, not assumed. The core SDK's dependency list is unchanged.
  - **A launcher activity of its own, plus `WailoPanel.show(context)`.** The icon means the panel needs no host code at all: opening it cold-starts the host's process, which runs `WailoStartupProvider`, so there is a live client behind it by the time it draws. `show` is for a host that would rather put it behind its own debug menu. Its `taskAffinity` is its own, so entering through the Wailo icon and pressing back leaves rather than dropping the user into someone else's app mid-flow.
  - **And a dynamic shortcut on the host's icon, registered from a second provider.** A launcher entry is one more icon in a drawer of two hundred, and some launchers and managed home screens do not show secondary entries at all — a debug tool nobody can find is a debug tool nobody uses. Long-pressing the app is where LeakCanary trained everyone to look. It is `addDynamicShortcuts`, never `setDynamicShortcuts`, and wrapped in a `runCatching`: the host's own shortcuts are not ours to drop, and the per-activity cap is a limit a real app can already be at — losing that race must not take someone's app down on launch. The shortcut is attached to the host's launcher entry explicitly, since `first()` on the query would attach Wailo to Wailo's own icon.
  - **Named for what it is, not for the variant it belongs to.** `sdk-android-debug` was the first name, mirroring iOS's `WailoSDKDebug`, and it was wrong on Android specifically: `debug` is a build-variant name here, so `wailo-android-debug` reads as *the debug variant of `wailo-android`* — a thing AGP really can publish — and the wiring line `debugImplementation(projects.sdkAndroidDebug)` says "debug" twice meaning two different things. `panel` is the word the docs already use for it. The "never ship this" part is carried by the `debugImplementation` boundary and the manifest check, which enforce it, rather than by a name, which only suggests it.
  - **Painted from the tokens through a private `CompositionLocal`, on `foundation` only.** Reading `MaterialTheme` would repaint Wailo in the host's brand, and a host on Material 2 — or with no Compose theme at all — would leave it unstyled. The same reason iOS hand-built its rows instead of using a `Form`.
  - **The merged Connect list (ADR-0047) is reduced to the four facts it needs.** `PanelDesktop` holds a `Remembered`, not a `WailoPairing`: the panel has no business holding keys, and the reduction is what makes the list logic testable — `WailoPairing`'s constructor is internal to `sdk-android` precisely so nothing outside can mint one.
- Alternatives considered:
  - **Ship the panel inside `sdk-android` behind `BuildConfig.DEBUG`:** rejected — the dependencies and the permission are in the release artifact either way, and a runtime flag is one bad merge away from a debug surface in production. The variant boundary is checked by the build.
  - **Use Material 3 and inherit the host's theme:** rejected — Wailo's panel looking like the app it is inspecting is a bug, not a feature; it has to be recognisably not-the-app.
  - **CameraX + `zxing-core` instead of `zxing-android-embedded`:** rejected — it is a scanner screen to write and maintain for an artifact nobody ships. The embedded library is one dependency and one `ActivityResultContract`.
- Consequences:
  - Anything a host wires itself needs the SDK's types, so `sdk-android` is an `api` dependency rather than `implementation`.
  - The launcher icon is the product mark, generated by Image Asset Studio from the master artwork: an adaptive icon plus density webps for the pre-26 fallback, every name prefixed `ic_wailo_panel`/`wailo_panel_` because library resources merge into the host's and a clash breaks someone else's build. Three things the wizard emits were dropped — the `_round` variants (nothing declares `android:roundIcon`), its duplicate background colour (the module already had one, and two copies of a value are two places to edit it), and the Play Store export (a debug-only artifact has no listing). `monochrome` reuses the foreground: a themed icon reads only its alpha.
  - `values`/`values-night` set the window background to the token background, so there is no white flash in dark mode between the activity opening and Compose's first frame.
  - Manual smoke: install the debug sample → two launcher icons, one of them Wailo, and long-pressing the host's icon offers **Wailo** as well. Open it either way → the panel draws with the app's traffic already streaming. Type an address, Connect, and watch the status line settle. Scan Studio's QR → it pairs. Check both light and dark (ADR-0016). Then install the release variant → one icon, no Wailo in the long-press menu, and no camera permission in App info.
